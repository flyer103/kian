# Code of conduct

This project is a technical space. Disagree about designs, benchmarks and trade-offs as hard as you
like; do not make it about the person.

## Expected

- Critique the change, not the author. "This breaks the fencing guarantee because X" is welcome;
  "you clearly do not understand distributed systems" is not.
- Assume competence. Someone asking a basic question is not wasting your time — the docs may simply
  be wrong, and pointing that out is a contribution.
- Respect the project's stated boundaries. A refused scope is a decision, not an insult; argue the
  decision with evidence if you think it is wrong.
- Keep secrets out of public threads. Provider keys, tokens, chat ids and personal paths belong in a
  private report, never in an issue.

## Not acceptable

Harassment, personal attacks, discriminatory language, sustained disruption, publishing someone's
private information, or pushing a security report into a public thread before a fix exists.

## Scope and enforcement

This applies to issues, pull requests, discussions and any other project space. Maintainers may
edit, lock or delete contributions that violate it, and may block accounts for repeated or severe
violations. Enforcement is at the maintainer's discretion and is not up for public debate.

Report a conduct problem privately to [@flyer103](https://github.com/flyer103) (or via the
[security advisory flow](https://github.com/flyer103/kian-runtime/security/advisories/new) if the two are
hard to separate). Reports are read by the maintainer only.

For security vulnerabilities, use [SECURITY.md](SECURITY.md) instead — do not open a public issue.
