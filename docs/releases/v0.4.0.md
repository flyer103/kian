# v0.4.0 — vision, voice, and a server that answers

The runtime becomes cheaper to observe and more honest about its failures: a liveness probe that
does not fold the store, a stop that releases the claim it cut, views that heal a stale schema, and
a `/metrics` scrape that answers in microseconds instead of minutes. Channels gain vision and voice,
and a self-dev request is an ordinary job run over a verified evidence pack whose publish step is a
conductor action, not a general command surface.

Two additive migrations land with it (channel dedupe, channel receipts); no event kind is added, no
session state machine changes, and KiandProto stays at v3.

## Channels: pixels, voice, and rows that settle

- **Channel images as vision references** (ADR-065). With `superagent.shaping.vision: true` an
  admitted channel image is a sibling `images` reference on the message, so a vision target reads
  the artifact's bytes as a content part while the wrapper keeps its exact text and the transcript
  line stays in place. Off by default; a text-only conversation is byte-identical.

- **A per-turn image budget** (ADR-066). `shaping.max_images_per_turn` (default 4) and
  `shaping.max_image_bytes_per_turn` (default 4 MiB) bound the images one turn renders; an image
  over budget stays text-only, one warning names the limits, and the persisted request is the audit
  record of what was admitted. Neither key boots without `vision: true`.

- **Voice in both directions** (ADR-067, ADR-078). Outbound text is the default; when the model asks
  a channel to speak, the iMessage edge delivers a spoken file and marks the `channel/delivered`
  payload `"voice": true`. Inbound voice notes are fetched, transcribed and admitted as a transcript
  line plus their metadata, the same path images take.

- **A multi-attachment row settles before it is admitted** (ADR-070). The adapter waits out the
  join-row lag with a bounded window, then admits what arrived and reports the placeholder and
  attachment counts instead of dropping the message or inventing content.

- **A fetch retries; a hole is named.** An attachment GET is idempotent, so a reset, closed body or
  timeout is retried three times with 200/400/800 ms backoff; a bridge refusal (401/404/409/413/503)
  never is. An item that still did not arrive keeps the row's metadata and is listed in payload
  `media_unavailable`, so the model and a transcript reader both see the gap. The bridge serves
  original attachments with a read-only streaming endpoint and an atomic HEIC-to-JPEG cache, and the
  legacy query route now resolves `rowid:index` ids, normalizes paths and allows self-sent
  attachments.

## Oversized requests: classify, budget, fold, audit

- **An oversized request is classified, not retried** (ADR-068): a carrier's
  `413 request_too_large` is its own non-retryable class instead of being reported as
  `provider_down`.
- **Byte pressure folds history before the turn exists** (ADR-072): the estimate is compared against
  the provider bound while the request is assembled, and the fold is the only prefix invalidation.
- **A fold happens only when the policy says so** (ADR-074): `compress_then_retry` folds and
  retries once; any other policy reports the classified failure.
- **Audit bodies carry artifact references** (ADR-073): a request's image parts persist as
  `artifact:<sha256>` references with `body_sha256` over the wire bytes, and the audit check says
  what it verified instead of silently skipping an inline body it could not digest.

## Self-evolution: a proposal pipeline, not an autonomous engineer

- **S1 propose** (ADR-069): a self-dev run is an ordinary job run over a verified evidence pack;
  `kian self evidence` builds the pack and `kian self inspect` answers what the runtime did in one
  window of the durable stream.
- **S2 publish** (ADR-071): a `publish` step turns the run's patch artifact into a local branch, or
  pushes a branch and opens one pull request. The step's artifact is derived from the child's final
  message, and a publish carries its own fixed sequence and receipt.
- **S3 land** (ADR-075): landing stays the owner's merge; `kian self verify --merged --base <ref>`
  verifies the digest chain read-only.

## Operator surfaces

- **`GET /healthz`** (ADR-076): liveness is a probe, never a fold. It answers `200` for a process
  that started and is serving, independent of `/metrics`.
- **A stop releases its drain** (ADR-077): `SIGTERM`/`SIGINT` cuts in-flight drains with
  `session/ended{interrupted}`, starts no new one, and exits 0 once ownership is released (bounded
  at 5 s).
- **`/metrics` is bounded by default**: a scrape reads the views projection; when no fresh view
  exists it returns a `degraded` body naming `views_unavailable` and the `?full=1` escape hatch
  instead of folding the whole store behind the request. `?full=1` keeps the old full derivation.
- **The workers board reads thread lineage** instead of rebuilding every session stream, so it
  answers on a production-scale store.
- **The drain hands its event cache out as a shared snapshot**: a model call no longer deep-copies
  the session's whole event vector, which was the dominant anonymous-heap growth on a 3.3 GB store.

## Read model and retention

- **A view proves its schema, not only its digest** (ADR-079): a stored payload whose schema version
  changed is discarded and rebuilt instead of failing to decode forever.
- **A full rebuild streams one session at a time** (ADR-080), bounding the peak of the tick.
- **A processed channel event never re-admits across session incarnations** (ADR-081): the dedupe
  key survives a session ending and rotating, and the receipt that proves it survives archival
  (ADR-082). An archived resident is never re-created, an archived session leaves no claim row
  behind, and an unreadable stream costs only its own session instead of the recovery batch.

## Upgrading

- Two additive migrations (v9 channel dedupe, v10 channel receipts) apply on boot; take the backup
  from the runbook first and expect the first start after the upgrade to be the slow one.
- KiandProto is still v3: a 0.3.0 `kiand` talks to a 0.4.0 `kian` and vice versa. Upgrade the
  server first, then the workers.
- `/metrics` changes shape by default: a monitor that expects `cache`/`usage` keys must either
  keep views fresh or opt into `?full=1` (which is O(store bytes) and unsuitable for a scrape
  interval on a large store).
- Vision, the per-turn image budget and spoken replies are all off unless configured; enabling them
  is a config change, no schema change.

## Install

Prebuilt archives (with `.sha256`) for `x86_64`/`aarch64` Linux and macOS,
`ghcr.io/flyer103/kian:0.4.0`, and crates.io:

```bash
cargo install kian-cli --version 0.4.0
cargo install kiand --version 0.4.0
```

From source:

```bash
cargo build --release --locked -p kian-cli -p kiand
```

The macOS bridge is built from source (`cargo build --release -p kian-imessage-bridge`); it is not
part of the archives.

## Boundaries, stated up front

- Vision is channel-scoped: pixels enter as artifact references on an admitted channel message, not
  as a general vision API, and they never rewrite prior context.
- Spoken replies exist on the iMessage edge only; text stays the default everywhere.
- `/metrics` `?full=1` still folds the store, and the views tick rebuilds rather than incrementally
  maintaining its projections (ADR-080 bounds the peak, it does not make it incremental).
- The self-evolution ladder ends at a verified proposal: publishing needs a configured remote, and
  landing is the owner's merge.
